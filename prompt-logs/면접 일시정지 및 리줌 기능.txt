## 0. Key decisions (recommendations)

| Topic | Decision | Why |
|---|---|---|
| Status | Add `"paused"` to `InterviewStatus` | Minimal; everything keys off status today |
| API | Extend `PATCH /api/interviews/[id]` with `status: "paused"` (+ `durationMs`, `currentQuestionIndex`). No `/resume` endpoint: resume is `POST /api/realtime/call` accepting `paused`. | `finish()` already PATCHes; `patchInterview` already handles status transition + hangup. The call route is the only place a call is born, so it is the natural resume point. |
| Accumulated time | Reuse `interviews.durationMs` as "accumulated active ms" (written at pause and at end). No new `active_ms` column. | List/review already display it (a paused row shows time so far), and server `pastLimit` can add it to the current segment. |
| Question index | New column `current_question_index` (0-based, nullable) written at pause; fallback derived from turns' `questionId` when null (crash case). | Exact when paused cleanly, robust when not |
| Recording | One blob per segment + new table `interview_recordings` keyed by `(interview_id, start_ms)`; replay picks segment by `turn.startMs`. Do not concatenate webm. | Concatenating Opus/webm needs remuxing (EBML cluster timecodes, cues) — fragile in-browser; `makeSeekable` only fixes metadata. Segment switching in a single `&lt;audio&gt;` is ~40 lines. |
| Resume context | Client sends saved turns as `conversation.item.create` messages over the data channel, then a system item, then `response.create`. Server appends a short "재개 프로토콜" to `instructions` in the session config. | Full fidelity (model sees exact prior Q&amp;A); the protocol text in instructions carries more weight for "do not restart from question 1". Summary-in-instructions loses what was answered. |
| Paused blocking new interview | Paused does **not** block `createInterview`. Resume (call route) is rejected with 409 if another interview is `in_progress`. | Paused costs nothing (no call). Blocking would force users to abort to practice something else. |
| Auto-abort | `hangupOverdueCalls`/`abortStaleInterviews` keep filtering `status = in_progress`, so paused is naturally exempt. | Requirement |
| Browser closed / disconnect | `end("disconnected")` → status `paused` (not aborted). `end("error")` stays aborted. Crash with no PATCH (status in_progress + callId) → the live page offers "이어서 진행" which PATCHes `paused` with server-estimated active time, then resumes. | Reconnect was out of scope only because time limits could be bypassed; with accumulated time tracked server-side that reason is gone. |

## 7. Edge cases

- Pause while interviewer is speaking: `flush()` marks the turn `interrupted` with the full transcript (deltas arrive ahead of audio). Resume system item asks the model to restate its last question. Replay shows "끊김".
- Pause while candidate is speaking: `flush()` emits partial text (or nothing if no deltas yet). Resume item tells the model the candidate may have been cut off.
- Pause while a turn POST is pending: already awaited before PATCH in `finish()`; keep that order.
- Pause then `start_question` tool call only (no message) in the last response: tracker index is persisted via `currentQuestionIndex`, so resume seeds correctly even without a turn carrying that `questionId`.
- OpenAI per-call cap: each resume is a new call, so the cap applies per segment; `maxMinutes &lt;= 60` validation stays.
- Two tabs resuming: conditional update in the call route; loser hangs up its own call.
- Pause PATCH never reaches the server (tab killed): row stays `in_progress` with `callId`; `hangupOverdueCalls` still protects cost; the live page offers "이어서 진행" via the estimate path. Local segment uploads via recovery once status is `paused`.
- `end("pause")` after `wrapUpSent`: refused in session + disabled in UI (within the last minute, just finish).
- Zero-length segment (pause immediately after resume): upsert on `(interviewId,startMs)` tolerates it; skip upload when blob is empty.
- `startedAt` resets on each resume (existing behavior); list ordering moves a resumed interview to the top — acceptable, note it in the schema comment.
